# AppleStoreInventoryTracker

一款查询附近 Apple Store 产品到店取货情况的 macOS 桌面应用，支持独立产品任务、系统通知和 Bark 推送。

## 使用

1. 在「 产品库存监控」点击工具栏 `＋`，从 Apple 中国大陆官网在售 iPhone 中选择机型、颜色和容量。型号由选择结果自动匹配，无需手动输入。
2. 添加产品时默认使用「配置」页的设置；打开「单独设置此任务」可调整地区、扫描间隔和通知。保存后任务独立使用自己的配置；需要变更时删除并重新添加。
3. 点击「保存」创建任务；「保存后开始」默认勾选，可取消后稍后启动。每条任务可单独开始、停止和删除。
4. 「配置」管理默认地区、基础扫描间隔、通知授权和默认 Bark URL，可手动发送测试推送。
5. 点击任务主体展开／收起门店库存与更新时间；右侧图标可开始／停止、删除任务或跳转 Apple 购买页，操作按钮不会触发展开。有货结果以绿色标记突出显示，停止监测或查询失败后的旧结果使用次要文字颜色。

商品目录在首次打开添加页时动态获取，缓存 24 小时，支持手动刷新。刷新失败保留上次完整目录；目录与库存扫描相互独立，暂时无货的配置仍可监控。

菜单栏图标只负责显示或隐藏主窗口；关闭窗口后监测继续，Dock 图标可重新打开窗口。退出应用会停止所有任务，有任务运行时需要确认。

任务配置自动保存，重启恢复列表但不自动开始监测。旧版逗号分隔的型号和查询配置会在首次启动桌面版时迁移。停止任务保留本次运行的最后结果，首次查询成功后会缓存产品名称、库存结果和已加载的图片，重启可直接展示；缓存库存标记为上次结果，重新查询成功后才恢复有货高亮。每条任务保存完整的独立配置（含 Bark 地址），默认配置的后续修改仅影响新任务；旧版继承默认值的任务会在首次加载时按当时生效值迁移为独立配置。同一型号可添加多条任务，分别使用独立的监控配置。

独立任务共用最多 3 个库存请求的并发预算；服务端冷却也由共用客户端约束。每条任务独立维护倒计时、加速阶段和通知去重状态。

监测过程中，确认有产品可取货后会自动切换为 15 秒查询；连续三轮成功查询均无货后，进入 30 秒查询的观察期，持续 5 分钟后恢复设置的间隔。单次加速最多持续 10 分钟，随后进入观察期；持续有货不会无限续期，再次从无货变为有货可重新触发加速。若设置的间隔更短，则保留更短间隔。倒计时会显示当前加速、观察或重试状态，服务端要求的冷却时间优先。

首次有货或新增可取货门店会立即提醒，相同库存状态的重复提醒间隔至少 60 秒。推送耗时不会阻塞库存查询。

监测期间应用会通过 macOS 官方活动 API 阻止空闲自动睡眠，允许锁屏和屏幕熄灭；停止监测或退出后恢复正常节能；进程被强制终止时，macOS 会回收该进程的防睡眠断言，无需重新打开应用。建议接通电源，持续监测会增加耗电。手动睡眠、合盖导致的睡眠及低电量强制睡眠不在此保证范围内；唤醒后会按实际经过的时间恢复查询，不补发错过的轮次，也不会跳过尚未结束的服务端冷却。

查询结果仅针对到店取货，实际可购买情况以 Apple 官网为准。请求失败时可能保留上一次查询结果。

## 开发与验证

使用 Xcode 打开 `AppleStoreInventoryTracker.xcodeproj`，选择 `AppleStoreInventoryTracker` scheme 运行。最低支持 macOS 14。

```sh
# 本地回归测试，不访问 Apple 或发送通知
./scripts/test.sh

# 强制终止独立测试进程，检查防睡眠断言回收（不会终止正在运行的应用）
./scripts/test-power.sh

# 实际库存查询和产品图片检查，不发送通知
./scripts/test.sh --live

# 编译
xcodebuild -project AppleStoreInventoryTracker.xcodeproj \
  -scheme AppleStoreInventoryTracker -configuration Debug \
  -derivedDataPath /tmp/apple-inventory-build CODE_SIGNING_ALLOWED=NO build
```

实时检查依赖 Apple 服务及型号销售状态，不固定断言有货数量。

代码按职责组织：

- `App/`：桌面窗口、应用生命周期与菜单栏显示／隐藏。
- `Views/`：分栏导航、任务卡片、任务编辑、全局配置、库存展示与退出确认。
- `Models/`：库存数据、产品展示属性、任务配置与默认值。
- `Monitoring/`：任务持久化与迁移、共享请求调度、监测协调、时钟、查询频率与通知策略。
- `Services/`：Apple 接口、响应模型、商品图片与通知发送。
- `Tests/`：离线回归与实时接口检查；`scripts/test.sh` 为统一入口。

## 购买辅助

配置页新增共用取货人信息、支付宝／微信付款偏好和浏览器登录入口。先安装 Google Chrome 与 Node.js（包含 npm），点击「准备购买辅助」安装固定版本的 Playwright Core；自动化使用独立 Chrome 配置目录，不读取日常浏览器密码。此开发版本需要本机 Node.js，尚未将运行时打包进应用。

在任务详情开启「有货时辅助购买」，从库存查询获得的门店中选择、排序和移除门店，单独选择是否加购 AppleCare+。保存后才开启，关闭 sheet 不会保存草稿。门店按列表顺序尝试，默认首个可用时段、数量 1、不折抵换购、个人发票。配置页以原生分段控件区分「监控默认值」和「购买辅助」：前者包含查询范围、扫描频率、库存通知；后者包含共用取货人、结账方式和浏览器。两类分别保存，切换分类保留草稿，不会因另一类资料未完成而阻止保存。

只有新的成功库存查询才会触发购买辅助，缓存结果不会触发。所有任务共用一个购买流程；到达检查订单页、登录失效或失败后暂停，避免重复加购。结束本次辅助会关闭该任务的辅助开关并释放浏览器，重新开启后才再次尝试。已有商品的购物袋不会被自动清空；请先在浏览器处理。用户自行确认订单和付款，应用不提交订单。

取货资料保存在 `~/Library/Application Support/team.chenjunren.AppleStoreInventoryTracker/PurchaseAssistant/profile.json`，仅当前用户可读写（0600），不进入任务快照、日志或命令行参数。原型的测试资料不会自动导入正式配置。

验证：40 项离线回归通过；独立 UI 副本验证了取消不启用、门店调整顺序／移除、保存及重启恢复，实际检查了精简 sheet 与配置页。官网商品页确认 AppleCare+ 为同组中的单个加购选项。原型曾完整跑通无 AppleCare+ 的支付宝流程至 Review；本次接入后的完整真实结账、AppleCare+ 与跨门店回退尚未端到端验证。

操作结果和报错统一使用窗口／sheet 顶部 toast：普通反馈 3 秒、错误 5 秒后自动关闭，可手动关闭；新反馈替换旧反馈并重新计时。扫描重复失败只在错误变化时提醒，避免轮询刷屏。表单、目录加载和购买辅助不再另行显示错误横幅或报错弹窗；删除确认和正常流程状态保留原有交互。

### Apple 账户登录

在「设置 → 辅助购买 → Apple 账户」点击「登录」，在 Chrome 完成登录后返回点击「我已登录」。App 自动关闭并重新打开自己的专用窗口，确认账户首页后显示「登录已保存」。这个状态表示上次验证成功；结账时仍会检查会话，失效后提示重新登录。

「重新登录」清理同一个专用 Chrome 内的 Apple Cookie、站点存储和浏览器缓存，保留 Chrome 偏好及 App 取货资料，不再创建新的资料目录。登录卡住时，可从等待登录状态旁的更多菜单选择「重新登录…」。不会影响日常 Chrome。旧版本的 `browser-profile.json` 仅用于继续使用原来选中的资料目录，新流程不再轮换该目录。

登录过程中不连接自动化；仅在清理登录数据或用户点击「我已登录」之后使用 CDP。此流程不自动填写凭据、不提交订单。已验证普通模式首次登录后可以接回自动化；网站内部转圈原因尚未确定，会话不保证永久有效。

离线状态测试：`./scripts/test.sh`；浏览器交接与站点清理测试：`node Tests/BrowserProfileTests.cjs`。

2026-10-22 实际验证：从新版 App 设置页依次完成登录、点击「我已登录」、重新登录及再次确认，两次均显示「登录已保存」。前后专用资料目录一致，没有新增目录，取货文件状态不变。实测中修复了 Chrome 退出时僵尸进程／残留锁造成的误报，并增加对应回归断言。

### 辅助购买诊断

卡片会保留暂停原因与失败步骤。每次浏览器流程在应用支持目录的 `PurchaseAssistant/Diagnostics/` 中记录步骤、耗时、退出码和错误分类，最多保留最近 20 次。不记录页面内容、URL、账号或取货资料。常见退出码：10 登录失效、11 购物袋校验未通过、12 无可用门店时段、13 AppleCare+ 不可用、24 浏览器连接或进程检查失败；20 需结合步骤和 `timeout` / `unexpected` 分类排查。

需要人工处理的暂停不会自动重试；处理后结束本次辅助并重新开启。诊断用于定位失败，不代表自动恢复或已验证该次结账成功。

辅助购买现按单产品模式整理购物袋：每次尝试清空后重新加入目标产品 1 件，确保 AppleCare+ 配置一致。该操作会影响同一 Apple 账户在其他浏览器中的购物袋。网络或页面超时（取货资料、付款及订单确认阶段除外）以 10、20、40、60 秒退避自动重试；无可用时段每 60 秒重试。关闭辅助购买、结束本次辅助或退出 App 会取消等待。已有 Review 页面、登录失效、资料或页面结构异常仍需用户处理，不提交订单。

2026-10-23 专用浏览器 541 对照：同一份 Chrome 资料去掉 remote-debugging 参数、完全不连接 CDP 后，通过界面删除商品仍跳转 `/shop/404`；同一个 Chrome、同一网络的无痕新会话中，相同规格商品加购成功，随后删除成功并显示空购物袋。这表明当前故障与原资料中的 Apple 网站会话状态相关，不能直接归因于正在连接 CDP。尚未定位到具体 Cookie / 存储项，也尚未验证重新登录后的自动化完整流程。不得将该对照结果表述为自动化已修复。

2026-10-23 结账实际验证补充：清理 Apple 网站会话并由用户重新登录后，普通模式删除成功；显式非零 CDP 端口下自动清袋、加购、进入结账成功。用户完成结账登录后，从当前取货页恢复，依次通过门店、首个时段、取货资料、付款方式，到达 Review，退出码 0；没有提交订单或付款。移除了被正常加购证伪的静态 `action="#"` 校验，保留真实导航结果与 541 诊断。相关对照和来源见 `docs/research/apple-monitor-541-comparison.md`。
